# RC.87 仅免费且可自动完成的渠道活动清单

## 用户验收目标
DSH 聚合路由管理页增加独立「渠道活动」导航。每个已配置或已识别渠道各有自己的表格，列为：活动名称、免费奖励数量与官方单位、是否有效、到期时间、执行状态。一个渠道没有满足条件的活动时展示空状态，不展示付费/购买/人工任务。

## 严格准入
- **免付费免购买**：活动领取动作不使用付费模型、购买、充值、订单、兑换码、外部发布或消耗额度；需购买会员才能进入的任务不擅自宣传免费。
- **已经存在可核验官方自动执行器**：内置来源渠道包的每日免费领取服务（CodeArts、Buddy、LobsterAI、Qoder、QoderCN、Trae、Loomy、MiniMax、ZCode）；独立 WorkBuddy CN/Global 的每日签到、独立赠送积分和补偿积分；豆包的每日网页签到；Lingxi 已验证的签到任务。其他渠道不因为有活动入口就被标记“自动领取”。
- **自动流程遵守原开关**：使用现有每日积分任务的全局和账号开关，绝不静默变更生产设置。官方二次确认才能记完成；WorkBuddy 活动的持久领取回执使超时或重启不重发；ZCode 验证码、无法证明免费/无权益时立即跳过。
- **活动资格非猜测**：已知关闭、无任务、需人工/验证码、已到期活动不纳入待自动执行列表；官方活动已经完成可展示“已完成”。尚未读到当日资格时只能标“待官方核验”，不可说“有效”。
- **金额不混淆**：只取具体活动官方奖励的 `credit/amount` 与有效单位，不用账号余额、模型费率、可领活动数或计划数替代。对 WorkBuddy 赠送/补偿显示官方积分；CodeArts 活跃积分套餐签到状态有官方 amount 时显示积分；其它来源官方没有返回明确单位与数量时显示“官方未公布”。
- **时间不编造**：WorkBuddy 官方 endAt、来源明确 endAt/expiresAt 用北京时间格式化；未返回则显示“官方未公布”，不能把每天签到的 23:59 当作官方到期时间。
- **安全与隐私**：不返回 Cookie、Token、凭据引用或任意上游原始对象；活动 GET 仅读取本插件已有只读状态；刷新操作是 DSH Connection Owner Peer 授权的 POST，只读官方状态并有防并发与 20 秒节流；不使用猜测端口或外部服务。

## 页面状态
- `有效 · 可自动执行`：官方明确领取资格或者该账号当日流程正在执行。
- `已完成`：官方或持久确认的今日签到/活动已领取。
- `待官方核验`：有免付费自动执行器但当前来源尚未给出明确当天资格，不能冒称完成。
- 排除：已知未开放、需要验证码或人工、收费购买、非已验证执行器的豆包其他任务、Loomy 需要真实操作的新手任务等。

## 验收
- 后端契约与清单过滤：tests/channel-activities.test.mjs。
- DSH Owner API 与跨域边界：tests/admin-hub.test.mjs。
- PC/移动端导航、各渠道独立表格、无活动空状态、刷新：tests/ui-panels.test.mjs。
- CodeArts 奖励数量不误认 ZCode 可领计划数：tests/embedded-pack.test.mjs；来源资料跨模块传递：tests/source-checkins.test.mjs。
- 全量 npm test、npm pack --ignore-scripts、GitHub Windows/Ubuntu CI。所有真实云端活动金额和到期时间仍须以实际登录账号返回为准，模拟测试不等于真实到账。

## 暂未覆盖
豆包非每日签到任务、Loomy 需操作的新手任务，以及其他渠道没有可靠免付费任务执行器的活动。它们被正确排除，不会混入本页或被标记自动完成；后续只有找到明确无人工/无购买的官方执行接口且能复核领取后才加入。

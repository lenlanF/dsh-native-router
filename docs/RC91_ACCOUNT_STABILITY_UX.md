## 实际安装现场核验
- 已在绑定 WebCodexTunnel Windows 电脑上使用文件元数据（不读取登录凭据正文）核查实际 DSH 插件安装：`.dsh/profiles/desktop/node_modules/dsh-native-router` 为 1.0.0-rc.90，而非旧 rc.84。
- 当前生产配置为 8 个启用 Provider、10 个启用账号，`account-verification.json` 记录 10 个身份状态（8 online、2 expired）。这些是最近的认证记录，不代表这次已经完成实时每个渠道的余额云端回查。
- DSH 运行中，管理 HTTP API 由 DSH Connection Owner Peer 保护。非授权读取 401 不能绕过；本次没有导出 Cookie、Token、凭据或强制更改自动任务开关，不主动实测收费模型。

## 修复账户名称／积分／余额时有时无
1. 新增 `src/account-public-facts-store.mjs`，只缓存公开可展示账号名、余额和单位、最近官方核验时间、近期临期积分。Hash(渠道/账号/凭据引用) 绑定身份，原子落盘（Windows 用户 DSH 插件私有目录），绝不存储 Cookie/Token/密钥正文。7 天 TTL、最多 200 账号、过期行单独清理、登出精确清除。
2. `account-center` 由驱动快照、最近已核实的公开资料和配置展示名分层合并；授权错误/临时限流/空数据不能抹掉以前有效的身份及余额；余额为 0 以及没有官方单位时也能显示。过期数据显示「上次记录」并保留上次核验时间，不冒充实时到账或登录有效。
3. `source-checkins` 跨渠道只读刷新成功但单账号缺席、或者部分响应缺少余额时，保存上次公开显示数值；**不会**保留上次 online 权限或“可领取”资格。绑定改变或账号被禁用时不跨账号复用旧数据。
4. `account-source-view` 合并同一物理账号多个本地来源时按确切 provider+accountId 选择最近官方数值，保留来源列表与现有模型权限，且只在展示数据来自备用来源时标记 cached；不同账号同名绝不混合数据。
5. 前端 `refreshRuntime` 在本次改为版本序列化批次：定时刷新、进入页面、手动刷新都只允许最新一轮写入页面。单个 REST 接口失败不清空原列表；新增可访问、具备读数和部分失败提示的同步状态栏。页面只读刷新不发模型请求、不签到、不修改授权。

## UI UX Pro Max 指导下的信息架构重做
- 核心导航变为：总览／渠道账号／渠道活动／每日积分任务／模型池 五个主工作台；授权复用、策略与故障恢复、JSON 运维收进可展开的三级导航，PC 左侧分组、手机端保留同一页目的完整下拉导航。
- 渠道账号列表按渠道折叠（首个默认展开、异常自动展开），新增「全部账号／仅看异常／有余额或积分」筛选和账号名搜索；默认按钮改为只读刷新和身份核验，可能消耗额度的批量模型推理操作收进高级操作并保留确认弹窗。
- 账号卡片的总余额／积分高优先级展示并有来源时间标签；最近过期积分与会员自然恢复额度不混为一项；换源读取缓存的字段明确标「上次识别／上次记录」，再也不把缓存值标成“实时核实”。
- 增大字号、点击热区、内外边距，视觉与 DSH 原生配色保持一致；低分辨率显示单列和最小 44px 触控控件，保留焦点可见与减少动画偏好。

# RC.93 — 统一渠道登录／按渠道签到／宿主模型指定／免费活动中心

## 1. 各自渠道管理登录
将原小米 MiMo、豆包、秒悟、千问办公、Amazon Quick 的独立登录、OAuth、扫码、Cookie 导入、设备码、接管操作恢复到各自原生 Provider 的账号分组内。此前错误地把这些登录放在一个额外的合并面板。各渠道仍与普通渠道一样支持账号列表、账号名称、余额积分、刷新、启停、解绑。保留原有安全认证，不会因打开设置页而发起登录或收费模型调用。

## 2. 只显示实际有签到执行器的渠道
签到中心的渠道列表只保留真实 checkinSupported 的 Provider，不会将只提供自然恢复额度、登录状态或活动广告的渠道列为签到。新增 checkin.channels 的按渠道 boolean 自动开关：未设置默认允许参与全局自动执行，false 则关闭该渠道自动执行。全局自动积分开关、来源池总开关、单个账号 autoCheckin 仍然同时约束；更改单渠道不会影响别的渠道。支持通过 owner-only 同源接口 /checkins/action 的 run-channel 按选中渠道逐个真实运行已有安全签到执行器。人工请求不受自动开关影响，但仍由既有历史回执防重复、授权/账号身份校验机制保护。

## 3. 本机登录态按已验证渠道分组
只将在线或最近真正验证过的账号按渠道 ID 展示，展开后有账号名称、最近验证状态、核验时间与公开余额。来源“发现”不代表“已登录”，旧过期的账号不冒充当前在线。来源池与独立接管账号均按正确渠道与账户标识归类，不复制凭据。

## 4. 宿主路由的模型范围限制
新增 hostModelSelection：Provider 没配置模型或列表为空代表所有模型；选中了一个或多个模型，便只将这些确切 ID 向本插件的宿主模型目录、AutoFree 目录、聚合路由模型目录和故障切换暴露。普通原生 DSH Provider 自身的独立路由不被越权更改。用户通过宿主路由与模型页的渠道模型复选框指定具体 ID、可一键恢复默认全部，保存配置后生效。过滤不仅是页面展示，实际宿主生成前、路由缓存、手动模型链、自动免费来源和 Agent 故障切换均执行校验。没有把未知费率判断为免费。

## 5. 渠道免费活动中心继续实现
真实具备已授权的免费、无感 API 活动执行器的渠道才出现「手动核验并领取免费活动」操作，指向 owner-only 同源接口 /activities/action 的 run-channel，逐账号调用 WorkBuddy / Loomy 等已有真实执行器并保留防重复。无法完成、需要付费购买、需要明显可感操作或没有官方钱包／账单正增量证明的任务不会被展示为已领取。保留所有渠道独立空表，未完成云端实时领奖的渠道不会被假报成功。

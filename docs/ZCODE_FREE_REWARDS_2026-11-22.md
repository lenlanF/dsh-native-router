## rc.75 业务缺陷与修复

1. 原跨渠道自动签到北京时间 10:05 开始执行，ZCode 晚间活动却约 19:00 才放卡。原任务可能把 3 次自动重试在放卡前用完，造成「每天发卡但插件无法领取」。**仅 ZCode 的自动领取资格起点改为北京时间 19:00**；其余渠道仍从 10:05 开始运行。手动早间查到无任务不妨碍晚间轮次。
2. ZCode 源签名活动接口返回 `active`、`claimable`、`planCount`，不返回其他渠道使用的 `available`。原插件共用条件强制 `available===true`，即使确切看到可领取 Start Plan 也会拒绝执行。新逻辑仅在 **准确选中的自有账号**、官方 `active===true`、`claimable===true`、正整数 `planCount>0` 时，才允许调用本插件独立源渠道的原生领取与验证码流程。
3. 官方显示零可领取计划时不执行验证码和领取，下一次状态更新可再次判断；当次官方明确受理且尚待确认时，不重复发送同一账号的晚间验证码/领取请求。保留所有独立账号启停与全局自动签到开关，**当前安装的全局自动签到默认关闭状态不自动修改**。
4. 新增 **一次性 inventory-audit**：在运行中的 DSH 逐一读取已启用账号的官方鉴权与模型目录，只保存匿名状态和来源计数，不调用推理、签到或付款；要求一次性 nonce 及明确只读授权，执行一次立即持久化消费。不能拿「模型列表可见」当「该账号已成功生成」。
5. 如果当前个人账号没活动卡，仍可继续核查其他渠道；判断是否免费最终只认可核验的官方入账额度，禁止免费 Start Plan 路由自动退化成收费 Coding Plan。

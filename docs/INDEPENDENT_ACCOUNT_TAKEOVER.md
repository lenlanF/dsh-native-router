# DSH 聚合路由：一次性接管与独立运行契约（rc.24）

## 目标与定义

**接管成功**不是已发现原登录态、原插件仍在线、或者路由能看到模型。它必须满足：用户明确授权迁移、来源账号有不可混淆的身份、凭据已保存在**聚合路由自身的 DSH Credentials 或私有账号池**，自有驱动直接访问上游接口且原插件不再参与其运行。

## 生命周期与禁止行为

1. **发现（discovered）**：经用户主动扫描，仅列出可用原插件账号候选、脱敏名称、来源和可迁移性。此步骤只读，绝不自动写入路由账号、模型链、原插件数据或原插件凭据。
2. **一次性导入（adopting）**：取得该账号的明确接管授权；使用精确原账号 ID 取回当前授权，校验格式并一次性写入自有 Credential/账号池，保存可验证的公开名称；失败不得标为已接管，也不得删除原插件授权。
3. **独立校验（owned_unverified）**：用户已拥有自有凭据，但还没有通过自有驱动的上游验证。不能只因发现或旧原插件在线就显示“已验证”；没有凭据不能静默退回原插件。
4. **独立运行（owned_verified）**：模型目录、推理、余额、签到及能实现的授权续期全部由本插件自己的自有驱动和凭据空间完成。原插件被停用、卸载、删除原登录态后，自有账号应保持同等功能。
5. **凭据失效（owned_expired）**：仅走本插件独立续期/重新授权；不得暗中重新读取、复制或要求启用原插件。无协议支持续期时明确报告需要一次本插件内的重新登录，不能伪造可用。

## 两种能力必须严格区分

- **独立接管**：自有凭据所有权和自有驱动已经建立；原插件只是最初的迁移来源。
- **实时引用/宿主路由**：登录凭据、鉴权或模型处理仍由现有 DSH Provider、已安装插件或桌面应用承担。它可以作为用户明确选择的临时连接模式，但**绝不应显示为独立接管**，原插件关闭可能导致这条引用失效。

## rc.24 实施约束

- `account-center` 不在展示或启动时回读 `installed-plugin-inventory` 的旧插件身份、余额及签到状态；只有本插件持久化的名称和自有驱动实时数据能成为自有账号的运行事实。
- `session-reuse` 不在启动、定时任务或后台悄悄扫描旧插件；普通扫描是只读发现。原有已配置的引用不做破坏性删除，新的扫描不再默默把它们当作接管结果。
- WorkBuddy、Loomy、ZCode 一次性导入时安全迁移可公开名称（不能保存 Token、完整手机号及内部密钥为姓名）；已有缺失名称时，必须走自有上游信息或显式一次性迁移，不回退长期依赖原插件缓存。
- 诊断字段 `runtimeMode=owned` 仅证明配置绑定是自有凭据格式；仅当自有驱动校验为 `online` 才展示“独立接管 · 已验证”。
- 只用频道/模型别名判定账号同一性不安全，必须精确绑定原账号及目标账号 ID。
- 手动发现的旧引用如需升级为独立账号，必须调用现有按账号授权的迁移流程，不自动重写用户已有模型链。

## 发行门禁

- 用假的原插件文件/凭据进行迁移后，在**删除原插件文件/服务并禁止访问旧 vault**的条件下运行模型、状态与签到测试。
- 运行账号页面与账号中心定时任务时，确认原插件读取计数为 0；独立运行时不依赖原插件 Provider 注册。
- 检查本机存量账号的 `owned` / `linked` 分布，并逐个完成独立验证，离线测试不得冒充云端验证。
- 检查授权过期、续期、重复登录去重、账号标识、模型价格更新、签到完成状态及原插件卸载后继续推理。
- 未能获得可安全迁移的完整授权时，只显示“来源引用/需要迁移或独立登录”，不得谎称已接管。

## 现阶段保留的迁移工作

历史存量 `sp_*` 但 Provider 仍是 `codearts` 等未使用 `own_*` 自有 Provider 的引用，需要进行精确账号对应、路由兼容和授权可用性检查，再通过明确接管动作迁入；不可直接修改字段或假定运行独立。特定来源不提供所需授权/续期能力时，需要单独适配并在本插件内完成认证。

# DSH 聚合路由：各渠道独立可用性验收矩阵（rc.25）

> **不是线上全部通过的声明。** 本矩阵区分：①自有凭据成功建立、②官方服务只读账号信息成功、③本账号真实模型推理成功、④可选的签到/续期成功。模拟回归通过不能替代真实账号网络调用。

## 统一契约

- **发现 != 导入 != 鉴权 != 推理。** 每个渠道必须由 `own_*` 自有账号凭据与自有驱动直接访问渠道官方服务。仅引用旧插件 `sp_*` 账号不得在账号中心直接伪装为接管成功。
- 首次迁移允许读取**一次**原渠道授权及公开名称；此后不能读取原插件的账号文件、凭据、余额、昵称、签到历史，也不能在原插件失效时静默回退。自有凭据续期必须由本插件发起。
- 每次查询从本插件自己的渠道包发出 `account.list`、`credits.status`、`credits.balances`，按精确账号 ID 匹配，并有独立错误状态。成功的**官方账号级状态或真实余额调用**才算只读鉴权；仅列出模型、扫描到账号、绑定凭据不是鉴权。实际推理成功另记 `modelInferenceVerifiedAt`。
- 显示名称只允许真实公开姓名/用户名或合规脱敏手机号；拒绝 `账号1`、`账号 #2`、`本机账号 1`、`来源账号`、`独立账号`、哈希摘要等伪名称。确实无法从渠道接口获得时显示“名称待获取”；不伪造余额、单位、已签到。
- 每个渠道的模型必须使用**自有授权**完成至少一次真实消息往返，才可标为“模型推理已实测”。不能靠其它账号或原插件代发成功证明本账号。
- 模型目录、倍率/资费、登录/刷新、积分/余额与每日签到均有各自状态；只执行渠道确有支持的操作。前后端不把客户端请求已受理判作签到成功。
- 自主登录/接管复用进入同一自有运行机制，仅在审计字段保留原来源差异。停用原插件后，仍需要有效官方授权或本插件独立续期。

## 其它已在本插件维护的渠道

- **own_workbuddy-cn / own_workbuddy-global**：独立 WorkBuddy 驱动与令牌续期，已有原插件移除后的隔离测试；正式在线模型实测仍要核对实际授权。
- **own_lingxi**：独立官方 API 余额与签到，已有原插件移除后的隔离测试；正式在线身份和推理仍需验证。
- **CodeArts 存量旧账号**：当前生产环境有一条非 `own_*` 的旧 `codearts` 引用。它不能因为在模型列表出现就算迁移完成；要按精确账号映射重新接管，并在不删除原账号前进行自有凭据实测。
- **MiMo、豆包工作**：参考渠道目录仍保留入口，但当前不是 13 个自有来源包的已实现适配器；没有自有授权/模型驱动时必须显示“待接入”，绝不展示为已验证或已支持推理。要实现需先取得可验证的官方授权与模型 API 适配。
- **自定义 OpenAI / Anthropic API 提供商**：由用户授权的自有 API Key 与相应协议直连，不依赖其它 DSH 插件。需独立按实际模型、配额与协议验收。

## 本轮可复现验证

- `node --test tests/source-owned-all-channels.test.mjs`：13 个渠道自有精确账号绑定，模拟官方信息读取、账户名/零余额、模型枚举与真实推理事件流、成功证据单独记录；不使用原插件数据。
- `node --test tests/embedded-pack.test.mjs tests/source-channel-driver.test.mjs`：官方账号证据、已签状态、模型事件协议、精确账号选择及异常回退。
- `node --test tests/*.test.mjs`：完整项目回归。
- `python tools/build-native-channel-pack.py --check` 及 `python tools/build-standalone-channel-pack.py --check`：上游来源包/单文件运行时锁定版本与审计核对。
- `tools/audit-release-package.ps1`、`tools/verify-packed-distribution.ps1`：源码隐私扫描、发行包边界以及真实 DSH 托管 Node 环境下的隔离安装/卸载。

**尚未满足的终局门禁：** 逐个真实账号、逐个渠道通过在线身份/余额/模型推理/刷新/签到验收，并在停用原插件后复测。上游没有提供的功能不能凭代码逻辑制造；必须明确范围并在本插件补对应适配。

# RC.81 — 已登录渠道账号名称与额度真实展示验收

## 与生产环境的直接核对
- 只读检查用户当前 DSH 安装确为 1.0.0-rc.80，8 个 Provider、10 条自有账号配置（包括新登录的小米 MiMo Desktop 1、豆包 1），全部最近一次官方身份缓存 online，宿主监听 9230。
- **身份校验 online ≠ 推理真实生成成功；账号配置存在 ≠ 账号昵称/额度 API 已返回。**
- 安装的账号展示公共模块与 GitHub rc.80 一致。发现实际产品级故障：官方账号资料在驱动内存丢失后虽然身份核验在持久缓存中保持 online，启动流程跳过资料读取，界面无法显示昵称和额度；MiMo 原驱动压根未查询会员额度；豆包把不同账期剩余额度相加为一个伪余额，且“未知”格式会被转成数值 0。

## 本版一体化修复
- **小米 MiMo Desktop**：通过自有授权的独立 mimopc SSO 读取 `/api/user/xiaomi/me` 的正式昵称，以及独立的只读会员端点 `/api/user/xiaomi/subscription/self`（会员 plan、剩余百分比、重置时间）；明确 **Desktop 会员权益与按量 API Token Plan 余额不是同一个计费账本**，故不给前者编造人民币/美元金额。单次 quota 查询限 7 秒，失败不撤销已验证身份。不接受 `null`、没有字段、不合法百分比作 0。
- **豆包**：官方 `/passport/account/info/v2/` 名称及订阅额度 `/alice/commerce/sale/subscription/quota/summary/`。每个窗口（套餐、周、五小时、赠送）独立公开，不相加；保留官方套餐名称和更新时间。未提供、空、无限制、错误额度值不伪造 0。
- **共用数据通路**：AccountCenter 仅给前端输出官方来源的非敏感白名单字段，防凭据泄漏；DSH 重启后首次启动会从各个自有驱动只读重载丢失的昵称/额度，不因持久化 identity cache 是 fresh 而跳过，不在每次页面渲染触发网络查询；按确切账号启停和绑定验证后读写。
- **界面**：渠道账号页面第一屏先展示用户已经登录的账号、实际名称/状态/额度/套餐/更新时间，所有技术 ID、原始引用和诊断折叠。四大块新增渠道登录说明收纳到可展开的“新增账号或重新登录”。采用适配 DSH Host 的有边界、有层次可响应账号卡，明确主次信息，提供“刷新账户资料”可见主操作，原本独立登录、模型实测、启停、解绑仍保留。

## 验收与剩余真实服务边界
- 真实用户账号的**配置、登录状态**已在原 Windows 宿主只读观察；但本次聊天没有 owner-authenticated DSH UI 会话，不能从其读取实际昵称/具体额度，也不能拿模拟官方响应替代生产数值证据。
- 对官方接口的 schema 和名义模型倍率有模拟测试，真实账户具体权益仍需要用户升级 rc.81 后以自己已经登录的账号进入页面刷新实际确认；不存在自动收费模型请求。
- 测试场景覆盖官方昵称、Desktop member 77.5% fixture、false 0 防护、豆包 80/100 package 与 12/20 week 分开显示、host restart once-only profile rehydrate、用户交互布局和所有旧账号/来源链路回归。
- 发布门禁：完整 Node 全量测试、真实 DSH 自带 Node 24 物理 tgz 解包、隔离 Cordis 13 源验证、MIT 53 源包安全补丁不变、发行文件全部哈希、隐私扫描及 GitHub Windows/Linux 双 CI；最后合并 GitHub main，用户自行升级，不直接触碰生产 rc80 登录账号文件。

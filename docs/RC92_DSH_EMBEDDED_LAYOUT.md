# RC.92 — DSH 内嵌设置页面：配置内容优先

## 真实问题

用户截图的 DSH「设置」弹窗已经有宿主侧栏。聚合路由 rc.91 又添加 220px 固定内部侧栏、20px 间隔和底部 sticky 保存按钮，实际账号卡片只剩很窄区域，文本与按钮严重挤压。根本原因是 UI 把 DSH 插件当作独立宽屏后台，使用浏览器窗口宽度判断响应布局，而没有使用 DSH 插件本身的宽度。本次在正确的 Windows 电脑确认实际已安装 rc.91，未变更生产安装、配置、登录凭据和账号。

## 界面整改

1. 单列配置主体：内部布局改为100%宽度，不再常驻第二个侧栏。仅容器宽度大于850px时提供顶部横向菜单；容器不足850px时自动改为紧凑的、保留全部10个模块的原生选择器。CSS 使用 container:dnr-workspace / inline-size，不依赖浏览器整个 viewport 尺寸。
2. 将保存配置、重新读取、来源同步状态放到账号内容前的常规工具栏（position:static），取消遮挡配置卡片的底部悬浮层。保留保存草稿提示和操作确认。
3. 保留全部渠道、登录、余额/积分、自动奖励、模型路由、注销及其他操作。允许长账号名、卡片信息、状态标签和按钮随局部宽度换行；避免表单或卡片撑出插件设置区域。
4. 渠道活动五列表格在窄容器中使用带每列标签的纵向信息卡片，不需要拖动整个页面寻找列。所有 CSS 严格限定在 dnr-shell，不影响 DSH 宿主设置和其他插件。

## Windows Chrome Headless 实际计算样式和宽度测试

命令：node tools/verify-embedded-layout.mjs

脚本读取真实 client.js 内的 UI_STYLES，在已安装的 Chrome 中创建类似 DSH 设置弹窗的嵌入布局（浏览器宽1440px，宿主左栏宽180px），分别设定 DSH 插件容器320、560、720和1024px。浏览器真实计算 DOM 宽度、菜单 display、保存栏定位、活动表格宽度和滚动溢出。脚本在 E:\\Temp 放置临时浏览器档案并清理；不访问 DSH/云端、账号或模型。

| 插件可用宽度 | 实际主区 | 内部菜单 | 横向越界 | 保存栏覆盖 |
|---|---:|---|---|---|
| 320px | 304px | 紧凑下拉 | 无 | 无 |
| 560px | 544px | 紧凑下拉 | 无 | 无 |
| 720px | 704px | 紧凑下拉 | 无 | 无 |
| 1024px | 1008px | 顶部横向导航 | 无 | 无 |

其余回归：node --test tests/ui-panels.test.mjs；完整回归：npm.cmd test。静态测试同时验证 container query、真实 DOM 中保存栏排在内容前、十个模块可选择、活动字段名不遗漏。

## 未夸大的验收边界

Chrome 使用真实生产 CSS 与仿宿主 DOM 的尺寸验收，不等于已经在用户安装的 DSH rc.91 中装入新版。当前用户的已登录账号和配置未被触碰。用户自行升级到 rc.92 后才能评价正式宿主里的视觉细节。

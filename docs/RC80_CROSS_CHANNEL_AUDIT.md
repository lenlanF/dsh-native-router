## 本轮已修复的具体可复现问题
1. 千问办公：官方账户上下文不带 organization_id 时，必须保留授权 Token 的企业组织；动态签名与账号缓存按 UID+组织绑定，远端企业身份切换拒绝跨组织签名模型请求。刷新 Token 的 JWT UID 或组织改变时，保留旧凭据而非覆盖其他账号。
2. 千问办公：官方设备码轮询中的暂时网络错误、429/503 不能直接变成终止状态；沿用原 PKCE challenge，指数节流再尝试，直到官方 5 分钟授权期满。并发轮询只能一个请求在途；明确 400/401/403 才终止。配置持久化失败必须撤回一次性完成回执。
3. 千问办公：最后一个完整 SSE 事件不带行尾换行时必须 flush，不能将真实已完成回答误判为失败；保留截断、空结果、工具事件及超时的硬门禁。
4. 秒悟：SSE 允许 LF / CRLF（包括跨 UTF-8 字节边界）；未结束单帧必须限 1 MiB，避免异常响应无限消耗 DSH 宿主内存。task_complete 也可能明确表示失败，不能把失败回合标为成功。
5. 秒悟：浏览器完成授权但用户取消，或元数据配置落盘失败，必须撤销仅属于这次授权的 Cookie，禁止下一次轮询重新提交一个已回滚的完成回执。即使碰到同名其他 Provider，直接 Cookie 接管也必须恢复/删除本次未提交的记录。
6. 豆包：Cookie 接管（包括手动输入）始终携带精确回滚凭证；未匹配事务的取消不再无条件删除已有账号。浏览器完成后取消、Provider 冲突与配置写入失败均按精确已写凭据处理；原账号保留。
7. 小米 MiMo：取消时要求完全匹配 Provider、ID 与引用；若相同账号已完成持久配置，绝不可删除其 Vault 密钥；重复登录遇到旧账号时不覆盖，也不删原始凭据。取消与浏览器状态异步操作均经 DSH 认证管理 API 等待完成。

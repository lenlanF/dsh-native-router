## 1. 证据分级和验收口径

| 级别 | 对应证据 | 是否足以宣布可用 |
|---|---|---|
| C—代码 | 适配器、登录与请求实现 + 可执行单元测试 | 否 |
| I—隔离 | DSH 托管 Node 中插件加载、路由、模拟上游正常结束、安全卸载 | 否 |
| A—在线账号 | 使用**本插件自有**凭据向官方来源进行只读远端身份校验，精准到账户 ID | 仅证明鉴权，不代表模型回复 |
| M—真实模型 | 该账号的自有模型调用收到完整有效回复、非空正文或合法工具回合；记录来源、模型、时间、失败原因 | 对已实测账号/模型才可声明可用 |
| R—独立性 | 原客户端、原 DSH 插件不再运行或不存在，仍能完成独立鉴权、模型回复、续期、余额、可用时签到 | 才能宣布该账号无上游宿主运行依赖 |
| S—签到 | 官方确切账号的“今天已领取”回执与回查，不能用 HTTP200/任务受理代替 | 仅对明确提供每日签到的来源适用 |
| F—Agent 续跑 | 真实 Host Agent 失败事件、备用模型完整回复和单次后续任务恢复，工具副作用不重放 | 完成真实故障链而非简单模型切换 |
| U—实际界面 | 运行中的 DSH 按实际帐号数据检查标签、筛选、模型弹层、按钮、窄窗口、超时/重复账号与遮挡 | 离线 UI 断言不能替代视觉与交互验收 |

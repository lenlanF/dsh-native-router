## 6C. rc.45 持久账号验证周期不因 DSH 重启重复请求

- 经过用户明确指出，重启时不该重复请求的核心修正不是“错误后重试更快”，而是**每个账号的有效证据属于绝对时间周期、不属于 DSH 进程生命周期**。原 rc.44 `autoCheckDue` 有周期判断，但 `accountCenter.refreshReadOnly` 和签到中心来源健康状态缺少跨重启复用，导致仍会重复访问官方接口。
- 复用现有无凭据 SHA256 账号绑定缓存与 `checkedAt`：在线15分钟、临时错误3分钟、过期/限流10分钟；重启、账号页反复打开、签到中心状态刷新不在到期前访问官方账号鉴权。过期后同账号并发只允许一个在途查询；首次接入或更改凭据绑定必须验证，人工明确刷新总能请求。
- 补充了**三次模拟 DSH 重启、五秒真实启动计时、官方查询次数零、跨绑定拒绝旧状态、恢复周期到期只查询一次**等测试。仅可宣称测试/隔离环境达到周期复用，不可据此宣称 rc.43 当前生产环境的六个失败账号已自动恢复。其他生产账号的余额与模型真实回复仍需后续验收。

## 6E. rc.47 模型目录与真实执行链的可用性门禁

- W2 红测复现并修复：自有渠道一账号 `listModels` 永久不返回，DSH 整个模型选择器以及健康的同渠道账号被拖住；不同 Provider 之间也因串行扫描相互阻塞；多个页面刷新造成重复只读目录请求。现在实现按账号/Provider 预算的有界取消、最多3账号和2Provider并行、同一模型目录在途请求合并。
- 退出、停用或切换账号绑定后，尚未返回的旧模型目录扫描不得发布旧登录才有的模型；通过失效修订号拒绝不符合当前授权快照的结果。
- 新增包含401帐号级失败的 NativeRouterAdapter 模拟端到端 DSH stream：第一个账号失败时第二个健康账号完成回复。**这属于I级隔离证据，不是M级真实模型服务证据**；尚需按单渠道与明确免费额度逐账号完成真实云端回合和原插件脱离运行验收。

## 6F. rc.48 Provider 级故障熔断与 Agent 工具输出不重放（隔离级）

- W4 红测确认：整个渠道 `PROVIDER_NOT_READY` 时，旧路由会继续尝试该 Provider 其他账号，而不是立即切换另一渠道；账号级冷却无法覆盖同 Provider 的其他模型。已建立独立 Provider 熔断与跨模型冷却，直到到期才再次尝试；单账号额度不足则仍可尝试同渠道另一个账号，避免过度封锁。
- 配置是动态授权，不能用一次请求开始前的旧快照作为整个回退链的执行许可。旧代码存在用户在上游调用尚未结束时禁用备用账号/Provider，仍调用被禁用备援的路径，现每一次新请求前实时复核 Provider、账号及凭据绑定，结果提交前再次验证，禁止失效账号提交工具调用/继续副作用。
- 新增真实 `NativeRouterAdapter.stream` 隔离模拟：私有来源包内一个渠道有两个账号且整体不可用，另一个自有渠道提供官方明确免费模型，连续三轮 AutoFree Agent 请求正常由备援完成，故障渠道总计只尝试一次。**这是隔离测试 I，不是实际 M/F 生产证据**，未触发任何线上模型、签到或配置变更。正式版仍需逐账号真实免费额度内调用与 DSH Agent 有工具任务验收。

## 7. 安全与用户参与边界

- 可自行继续：只读项目/本机安装和状态审计、GitHub/Gitee 上游比较、完整离线单测、包安全检查、隔离 DSH 安装、明确失败的源码修复和 GitHub `main` 更新。
- **需要明确授权/生产条件**：真实模型推理（即使自认为免费也可能消耗服务额度）、发起签到领取、创建/修改模型链或启用 Host Failover、扫码登录/账号绑定、真正卸载原渠道插件或改变 DSH 当前配置。
- 对尚未完成的在线账号模型验收，正确结论始终是“待验收”，不得用 13 适配器、8 个旧 online 记录或 100% 模拟测试通过来替代。

# 全渠道“无原客户端进程”独立运行验收门禁（RC.29）

## 不可妥协的架构规则

无论是 MiMo、豆包、WorkBuddy、Lingxi、Loomy、ZCode、CodeArts、Qoder、TRAE 等渠道，原桌面客户端、原 DSH 插件或它们的额外网关，均不是**已完成授权接管的账号**在查询身份、余额、签到、推理和续期时的运行依赖。原客户端甚至可以从未安装过：只要当前渠道支持独立网页登录等自有授权方式，就可从聚合路由直接登录。

- **一次性授权**：可只读发现用户本人原客户端的已有会话，也可由本插件启动普通浏览器直接网页登录/扫码；不自动扫描、修改或窃取其他软件凭据。没有原客户端时，走自有网页登录路线。
- **存储归属**：用户确认接管后，账号、区域与所需授权写进本插件的私密 DSH Credentials / 自有渠道账号池；配置只保存精确凭据引用。首次凭据写入与公开账号配置保存不一致时要可恢复/回滚。
- **运行路径**：选用 `own_*` 的精确账号驱动，直接访问相应会员/客户端认可的远程服务；不用原插件导出的账号列表、客户端本地端口、原应用运行进程、后台网关或原插件的自动刷新服务。临时普通浏览器只在主动授权期间启动；授权后关闭，不参与模型推理。
- **独立更新**：服务端仍会要求有效的账号会话、正常的身份验证及网络连通。凭据到期后应使用本插件的原生刷新机制，不能刷新时提示重新在本插件授权；不保证上游永不过期或所有会员权益永久保留。
- **准确展示**：旧 `dsh-host` 路由/未接管的宿主 Provider 引用只能标为“宿主委托/待接管”，不等于独立账号。真正属于本插件的准确账号引用也不等于已通过在线鉴权；必须将账号在线、可用模型、真实成功模型回合区分展示。
- **签到与工具**：用本插件直接查询/领取相应渠道的接口并复核回执；只要某渠道后台没有确认完成，就不能显示签到成功。无法从网页登录执行的桌面 Agent 工具必须保持不支持/未核验，不能暗中启动原客户端当做兜底。

## 尚不可宣称的结果

- 上述为**隔离模拟完成**，不代表 13 个渠道或 MiMo/豆包真实生产账号的线上推理、刷新及签到都已经验证。
- 旧渠道原始引用不会被静默转换为本插件凭据。迁移必须经过明确的拥有者授权；完成迁移后才能要求其不依赖原来源运行。
- 有些渠道采用官方客户端会员协议而非商业 API；上游正常登录验证、权限变化、风控或套餐到期仍可能造成请求失败。不得通过商业 API Key 偷换成另一个不等价渠道。
- 发正式版前，必须用真实授权在原应用和原插件**全都不存在**的条件下，逐渠道验证账号资料、单轮模型回合、断点重启、自有令牌续期、实际签到回执和账户撤销；未通过的渠道应保持“待验证”而非写“正常可用”。
